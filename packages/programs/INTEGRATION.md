# `hooked_rooms` — Server & Client Integration

How off-chain code (server, client, scripts) interacts with the on-chain
program. Read this whenever the program changes — it's the contract between
the program and everything that talks to it.

Program ID: `4ERUTWVN3aJP5tghEcZNd555NGcK3Jr8B21mnBB8JSMg`

---

## 1. IDL sync — do this on every program change

The program publishes its ABI as an IDL. **Three** copies live in the repo:

| Path | Purpose |
|---|---|
| [`packages/programs/target/idl/hooked_rooms.json`](target/idl/hooked_rooms.json) | Canonical IDL, regenerated by `anchor build` |
| [`packages/programs/target/types/hooked_rooms.ts`](target/types/hooked_rooms.ts) | TS type helper, regenerated by `anchor build` |
| `packages/server/src/idl/hooked_rooms{.json,_types.ts}` | Server's compiled-in copy |
| `packages/client/src/idl/hooked_rooms{.json,_types.ts}` | Client's compiled-in copy |

After **any** change to `programs/hooked-rooms/src/`, run:

```bash
cd packages/programs && NO_DNA=1 anchor build

cp target/idl/hooked_rooms.json   ../server/src/idl/hooked_rooms.json
cp target/types/hooked_rooms.ts   ../server/src/idl/hooked_rooms_types.ts
cp target/idl/hooked_rooms.json   ../client/src/idl/hooked_rooms.json
cp target/types/hooked_rooms.ts   ../client/src/idl/hooked_rooms_types.ts

cd ../server && pnpm build      # tsc — should pass
cd ../client && pnpm build      # tsc -b && vite build — should pass
```

If either build breaks, the IDL change introduced a breaking ABI change
(new required account, removed ix arg, struct rename). Either fix the call
site or roll the program change back.

## 2. Account auto-resolution

[`Anchor.toml`](Anchor.toml) has `resolution = true`, which means Anchor's
TS client auto-derives PDAs whose seeds are constants in the IDL. For our
program, that means `config`, `roomVault`, `entry`, `registry`, and
`systemProgram` are auto-fillable; you only need to pass the accounts that
require external knowledge (signer keypairs, the room's user-provided ID,
treasury/lp_manager pubkeys).

**Practical rule:** in `.accounts({ ... })` you can omit anything that is a
PDA the IDL knows how to derive. The library will fill it in. You **must**
still pass:

- the `signer` (whichever role: `admin`, `authority`, `keeper`)
- accounts whose addresses come from on-chain state (e.g. the `room` PDA
  itself when calling `deposit_room`, since the room ID isn't a constant)
- accounts pinned to mutable config values (`treasury`, `lp_manager`) when
  the IDL doesn't know their addresses

This is why the existing server code already works without modification
after the pause-switch refactor: it explicitly passes `room`, `roomVault`,
and `admin`, and Anchor auto-resolves the new `config` requirement.

## 3. Per-instruction account inventory

What every state-changing ix expects, after the pause-switch + version
refactor. **Bold** = required from caller. *Italic* = auto-resolved by
Anchor when `resolution = true`.

### `create_room(room_id: u64)`
Caller: admin keypair (today: server). Auto-creates the room PDA and the
SOL vault PDA.

- **`admin`** — signer, fee payer, becomes `room.admin`
- **`room`** — derived: `["room", room_id_le]`
- *`room_vault`* — derived: `["room_vault", room_pda]`
- *`config`* — `["config"]`, used only for `paused` check
- *`system_program`*

### `deposit_room(deposit_lamports: u64)`
Caller: any user. Creates a per-user `RoomEntry` PDA on first deposit.

- **`authority`** — signer, fee payer, becomes `entry.authority`
- **`room`** — looked up by ID off-chain, passed in
- *`room_vault`* — derived from room
- *`entry`* — derived: `["room_entry", room_pda, authority]`
- *`config`*
- *`system_program`*

### `close_room(yield_lamports: u64)`
Caller: admin keypair.

- **`admin`** — signer
- **`room`** — passed in
- **`treasury`** — must equal `config.treasury` or fails `TreasuryMismatch`
- *`room_vault`*, *`config`*

### `return_principal(yield_share_lamports: u64)`
Caller: admin. Once per `RoomEntry`.

- **`admin`** — signer
- **`room`** — passed in
- **`recipient`** — must match `entry.authority` (enforced by entry seeds)
- *`entry`* — derived: `["room_entry", room_pda, recipient]`
- *`room_vault`*, *`config`*

### `finalize_room()`
Caller: admin. Sweeps any vault remainder to treasury and closes the room.

- **`admin`** — signer
- **`room`** — passed in
- **`treasury`** — must equal `config.treasury`
- *`room_vault`*, *`config`*

### `withdraw_to_lp_manager(amount: u64)`
Caller: admin. Moves principal to the LP service hot wallet during the LP
deploy window.

- **`admin`** — signer
- **`room`** — passed in
- **`lp_manager`** — must equal `config.lp_manager` or fails `LpManagerMismatch`
- *`room_vault`*, *`config`*

### `update_room_entry_score(score_delta: u64)`
Caller: gateway keeper (Pulse worker). Cumulative score updates, with
top-3 leaderboard maintained on-chain.

- **`keeper`** — signer, must be in `GatewayRegistry.keys`
- **`room`** — passed in
- **`entry`** — passed in (or auto-derived if you pass the authority)
- *`registry`*, *`config`*

### `set_paused(paused: bool)` — admin emergency switch
- **`admin`** — must equal `config.admin`
- *`config`*

### `init_program_config(treasury, lp_manager)` — bootstrap, run once
- **`admin`** — signer, fee payer, becomes `config.admin`
- *`config`*, *`system_program`*

### `init_gateway_registry(initial_keeper)` — bootstrap, run once
- **`admin`** — signer, fee payer, becomes `registry.admin`
- *`registry`*, *`system_program`*

PDA helpers live in [`solana/roomsProgram.ts`](../server/src/solana/roomsProgram.ts):
`getRoomPda`, `getRoomVaultPda`, `getRoomEntryPda`, `getGatewayRegistryPda`,
`getProgramConfigPda`.

### Recommended pre-flight: read `config.paused` before queuing work

Right now the server fires keeper txs and lets the program reject if
paused. That works, but burns RPC calls and creates noisy error logs.
Before queuing keeper or lifecycle jobs, read the config once and skip:

```ts
// services/configCache.ts (new)
import { getProgramConfigPda, getRoomsProgram } from "./solana/roomsProgram.js";

let cachedAt = 0;
let cached: { paused: boolean; admin: string } | null = null;
const TTL_MS = 5_000;

export async function getProgramConfigCached(adminKp: Keypair) {
  if (cached && Date.now() - cachedAt < TTL_MS) return cached;
  const { program } = getRoomsProgram(adminKp)!;
  const cfg = await program.account.programConfig.fetch(getProgramConfigPda());
  cached = { paused: cfg.paused, admin: cfg.admin.toBase58() };
  cachedAt = Date.now();
  return cached;
}

// Usage in roomKeeper.ts before each job
const cfg = await getProgramConfigCached(adminKp);
if (cfg.paused) {
  logger.warn("ProgramConfig.paused=true — skipping keeper run");
  return { skipped: true, reason: "paused" };
}
```

5-second TTL because pause is an emergency action; you want it to take
effect almost immediately but not at the cost of spamming `getAccountInfo`.

### Recommended: detect `Paused` in error responses

```ts
import { AnchorError } from "@coral-xyz/anchor";

function isPausedError(err: unknown): boolean {
  if (err instanceof AnchorError) {
    return err.error.errorCode.code === "Paused";
  }
  const msg = err instanceof Error ? err.message : String(err);
  return /Paused/.test(msg) || /custom program error: 0x1796/.test(msg);
  // 0x1796 = Anchor offset (6000) + Paused (26th error in errors.rs).
  // Verify against target/idl/hooked_rooms.json under "errors" if you
  // bump the enum order — it changes silently otherwise.
}
```

Wrap every `.rpc()` call with this; if `paused`, retry with backoff
(typically 30s–5m) instead of bubbling the error.

### Pause toggle CLI

Add a script — admin-only, mirrors [`initProgramConfig.ts`](../server/src/cli/initProgramConfig.ts):

```ts
// packages/server/src/cli/setPaused.ts
import { loadAdminKeypair, getRoomsProgram, getProgramConfigPda } from "../solana/roomsProgram.js";

async function main() {
  const desired = process.argv[2];
  if (desired !== "true" && desired !== "false") {
    console.error("Usage: pnpm tsx src/cli/setPaused.ts <true|false>");
    process.exit(1);
  }
  const admin = loadAdminKeypair();
  if (!admin) { console.error("ADMIN_KEYPAIR not set"); process.exit(1); }

  const { program } = getRoomsProgram(admin)!;
  const before = await program.account.programConfig.fetch(getProgramConfigPda());
  console.log(`paused: ${before.paused} → ${desired}`);

  const sig = await program.methods
    .setPaused(desired === "true")
    .accounts({ admin: admin.publicKey } as never)
    .rpc();
  console.log("tx", sig);
}
main().catch((e) => { console.error(e); process.exit(1); });
```

`ADMIN_KEYPAIR` must hold the keypair whose pubkey equals
`ProgramConfig.admin` on-chain. The CLI checks this before sending and
exits with a clear message if they don't match.

## 5. Client integration patterns

### Where the client signs txs

Today the client only calls `deposit_room` from
[`components/onboarding/deposit-screen.tsx`](../client/src/components/onboarding/deposit-screen.tsx).
The user's wallet signs; no admin/keeper privileges client-side.

### Recommended: surface paused state to the user

When `config.paused === true`, the deposit button should be disabled with a
helpful message instead of letting the user submit a tx that will fail
on-chain. Add a hook:

```tsx
// packages/client/src/hooks/use-program-paused.ts
import { useEffect, useState } from "react";
import { useConnection } from "@solana/wallet-adapter-react";
import { getProgramConfigPda, getRoomsProgramReadonly } from "~/utils/anchor";

export function useProgramPaused() {
  const { connection } = useConnection();
  const [paused, setPaused] = useState<boolean | null>(null);

  useEffect(() => {
    let cancelled = false;
    const tick = async () => {
      try {
        const program = getRoomsProgramReadonly(connection);
        const cfg = await program.account.programConfig.fetch(getProgramConfigPda());
        if (!cancelled) setPaused(cfg.paused);
      } catch {
        // Account doesn't exist yet (pre-init) → treat as not paused.
        if (!cancelled) setPaused(false);
      }
    };
    tick();
    const id = setInterval(tick, 30_000);
    return () => { cancelled = true; clearInterval(id); };
  }, [connection]);

  return paused;
}
```

Wire into `DepositScreen`:

```tsx
const paused = useProgramPaused();

const canSubmit =
  isValidDepositAmount(amount) &&
  !loading &&
  !!publicKey &&
  !!anchorWallet &&
  !!openRoomId &&
  paused === false;     // <- gate UI

const statusMsg =
  paused === true
    ? "Deposits are temporarily paused for maintenance. Check back shortly."
    : !publicKey ? "Connect your wallet to deposit." : ... ;
```

`getRoomsProgramReadonly` is a small helper that returns a `Program` with
no signer (read-only); add it next to `getRoomsProgram` in `utils/anchor.ts`
if it doesn't exist:

```ts
// utils/anchor.ts (add)
import { AnchorProvider, Program } from "@coral-xyz/anchor";
import { Connection, Keypair } from "@solana/web3.js";
import idl from "~/idl/hooked_rooms.json";
import type { HookedRooms } from "~/idl/hooked_rooms_types";

export function getRoomsProgramReadonly(connection: Connection) {
  // Provider needs *some* wallet object; readonly calls never sign, so a
  // throwaway keypair is fine. Crucially, do NOT use the user's wallet here —
  // that risks accidentally surfacing a sign prompt for read paths.
  const dummy = Keypair.generate();
  const wallet = {
    publicKey: dummy.publicKey,
    signTransaction: async () => { throw new Error("readonly"); },
    signAllTransactions: async () => { throw new Error("readonly"); },
  };
  const provider = new AnchorProvider(connection, wallet as never, {});
  return new Program<HookedRooms>(idl as never, provider);
}
```

### Error parsing on the client

The client doesn't currently distinguish on-chain error codes. If you
want to surface `Paused` differently from generic errors:

```ts
function classifyDepositError(err: unknown): string {
  const msg = err instanceof Error ? err.message : String(err);
  if (/user rejected/i.test(msg)) return "Transaction rejected.";
  if (/insufficient/i.test(msg))   return "Insufficient SOL balance.";
  if (/Paused/.test(msg))          return "Deposits are paused — try again later.";
  if (/RoomFull/.test(msg))        return "This room is full.";
  if (/RoomCapacityExceeded/.test(msg)) return "This deposit would exceed the room cap.";
  if (/RoomEntryWindowClosed/.test(msg)) return "Entry window for this room has closed.";
  if (/already in use/i.test(msg)) return "You've already deposited to this room.";
  return `Deposit failed: ${msg}`;
}
```

## 6. Account version awareness

Every account now carries `version: u8`. Today every fresh account is
written at version `1`. When a future program upgrade adds a field:

1. Bump the relevant `*_VERSION` constant in
   [`programs/hooked-rooms/src/state.rs`](programs/hooked-rooms/src/state.rs).
2. Move the new field bytes out of `_reserved` (shrink the array).
3. In each ix that **reads** the account, branch on `account.version`:
   ```rust
   match room.version {
       1 => { /* legacy: don't read new field */ }
       2 => { /* new: read new field */ }
       _ => return err!(RoomError::UnsupportedAccountVersion),
   }
   ```
4. Optionally ship a `migrate_room(...)` ix that mutates `room.version = 2`
   and writes the new field into the freed `_reserved` bytes.

**On the client/server side**, after the IDL refresh:
- Old code (compiled before the upgrade) still reads v1 accounts fine
  because the new field lives where `_reserved` used to be — same offset.
- New code that needs the new field should read `acct.version` and either
  use the new value or trigger migration.

The reserved-padding strategy means **adding a field never requires a
realloc on existing accounts** (you reuse padding). Removing or reordering
fields still requires a migration ix.

## 7. Authority model

Five keypairs are involved end-to-end. Most environments use a single
hot keypair per role; pubkeys are recorded on-chain and the program
enforces matches before mutating state.

| Authority | Held by | What it can do |
|---|---|---|
| Program upgrade authority | deployer keypair (BPF Loader Upgradeable owner) | push new bytecode via `solana program upgrade`, or relinquish via `--final` |
| `ProgramConfig.admin` | `ADMIN_KEYPAIR` env var | `set_treasury`, `set_lp_manager`, `set_paused` |
| `GatewayRegistry.admin` | bootstrap signer (today: `~/.config/solana/id.json` on devnet) | `add_gateway_key`, `remove_gateway_key` |
| `Room.admin` | server keeper key (sets itself at `create_room` time) | `close_room`, `return_principal`, `finalize_room`, `withdraw_to_lp_manager` for that room |
| Gateway keepers | `KEEPER_KEYPAIR` (Pulse worker) | `update_room_entry_score` (must be in `GatewayRegistry.keys`) |

`ProgramConfig.treasury` and `ProgramConfig.lp_manager` are **destinations**,
not signers — they hold pubkeys that other ix verify (`TreasuryMismatch`,
`LpManagerMismatch`). The treasury wallet only needs to sign when *spending*
protocol revenue, which happens off-chain in regular Solana wallet UX.

**Bootstrap order** (one-time per cluster):

1. `solana program deploy` → upgrade authority is the deployer keypair.
2. From the admin keypair: `pnpm tsx src/cli/initProgramConfig.ts`
   (creates `ProgramConfig` with admin/treasury/lp_manager pubkeys pinned).
3. From the bootstrap signer: run the gateway-registry init script
   (`tests/setup/init-gateway-registry.ts`) once; this writes
   `GatewayRegistry.admin` and the first keeper pubkey.

Verify with:

```bash
solana program show 4ERUTWVN3aJP5tghEcZNd555NGcK3Jr8B21mnBB8JSMg --url $RPC
SOLANA_RPC_URL=$RPC pnpm tsx src/cli/inspectProgramConfig.ts
```

### Reducing single-key risk without coordinating signers

If you want to harden the admin without introducing multi-signer flows:

- **Hardware wallet for `ADMIN_KEYPAIR`.** Ledger holds the secret; you
  plug it in to run `setPaused.ts` or `set_treasury` and unplug after.
  The on-chain authority pubkey is unchanged.
- **Final program freeze.** `solana program set-upgrade-authority <PROGRAM_ID>
  --final` makes the bytecode immutable. Irreversible — only run after a
  long stable period and after you're confident the pause switch covers
  any operational lever you'd want.
- **Drop the admin entirely.** After init, run `set_treasury` and
  `set_lp_manager` once to lock in destinations, then there's nothing
  left to call as admin except `set_paused`. If you accept losing the
  emergency switch, you can rotate `ProgramConfig.admin` to a pubkey
  whose secret you've destroyed (effectively burning the role).

## 8. Risk notes when changing this contract

- **Breaking ABI changes** (adding a required account to an ix, renaming an
  ix, changing arg types) will silently break any consumer that hasn't
  refreshed its IDL. Always run §1 after touching the program.
- **Reordering errors in `errors.rs`** changes their numeric codes. Anything
  that pattern-matches on `0xN` instead of the symbolic name (e.g. cached
  Sentry rules, log-grep alerts) will break silently. Append errors to the
  end of the enum, never insert.
- **Removing a field from an account struct** is a hard migration and risks
  reading garbage from old accounts. Use the version field + migration ix
  pattern in §6 instead.
- **Pause is an admin-trust action**, not a security boundary against
  bugs in the gated ix themselves. If `deposit_room` has a logic flaw, a
  paused program is safer but the flaw still exists and ships when you
  unpause. Treat pause as breathing room to push an upgrade, not as a fix.
